## Key Decisions

- Capture is the **default verb**, not a subcommand. `src/main.rs` reads `std::env::args_os()`, runs `peel_root` over it, and only then inspects the first remaining argument with `id::looks_like_id` before clap ever parses, routing to `run_capture`. `looks_like_id` is lax about *validity* and strict about *shape*: it wants a family-shaped token (starting with an ASCII letter, then letters, digits or underscores), a hyphen, and a first level that **starts with a digit**. The laxness is what routes a typo like `SEND-1.a.b`, or a wrongly cased `send-2`, to capture's error message instead of clap's "unknown subcommand"; the digit rule is what keeps an ordinary hyphenated word such as `spec-sync` or `well-formed` from being read as an id at all. The same predicate decides what a criterion line is inside `doc`, so both halves matter (`cli::a_wrongly_cased_id_is_reported_rather_than_read_as_prose`, `cli::an_ordinary_hyphenated_word_is_not_mistaken_for_an_id`).
- **`--root` must be peeled before the dispatch, not after, and only from the front.** Capture never reaches clap, so without `peel_root` the flag and its value would be `join(" ")`d straight into the criterion's sentence (hi: CAPTURE-8). `peel_root` handles both `--root PATH` and `--root=PATH` and hands the value to `run_capture` as the start directory for `Workspace::find`. It consumes those forms only while they are still *leading*: the loop `break`s at the first argument that is neither, so once the id has appeared, everything after it is the person's sentence and a word that happens to read like a flag stays a word (hi: CAPTURE-9). That is the whole meaning of CAPTURE-8, "I put hi's own options before the id". Two regressions guard it: `cli::root_is_honored_by_capture_and_not_swallowed_into_the_sentence` asserts the string `--root` never appears in the file when the flag leads, and `cli::a_flag_looking_word_inside_a_sentence_stays_a_word` asserts it does appear, intact, when it is part of the sentence.
- **`args_os`, not `args`.** `std::env::args()` panics on a non-UTF-8 argument. `main` collects `OsString`s and converts each one, reporting `that sentence is not valid UTF-8`, followed by `hi files are text, so it cannot be stored as written`, with exit 1 instead of a backtrace (hi: CAPTURE-1.c). Do not simplify this back to `args()`.
- The sentence arrives as `rest.join(" ")`, so an unquoted sentence works as well as a quoted one. Capture receives one already-joined string and must not attempt to re-split it.
- **A new id just works; an existing id refuses.** This is the whole rule, and the existing-id refusal is the only content-driven failure in the module. Everything else that fails is malformed input.
- **A new family creates its own file with no prompt** (hi: CAPTURE-2.a). The alternative of asking "which file?" was rejected in DECISIONS.md §6 because stopping to answer a question is exactly what loses the thought. The accepted cost is that a mistyped family silently creates a stray one-criterion file; that is visible in `hi check` as a family holding a single criterion, and the fix is a rename.
- **Check order is fixed and load-bearing**: id grammar → sentence → already-exists → missing parent → resolve/create file → insert → save. Every refusal sits above every write, which is what makes hi: CAPTURE-5 ("if hi refuses for any reason, nothing is written to disk") true rather than aspirational. Do not move a validation below the `create_file` call.
- The duplicate check runs **before** the parent check on purpose: if you retype an existing sub-id, the more useful message is "that already exists, here is the next free number", not "your parent is missing".
- **The destination is resolved parent-first, and that ordering is load-bearing.** `capture` computes `parent_file` from `Workspace::find_id(&parent)` and only falls back to `workspace.doc_for_family(&id.family)` when that is `None`. This is what closes the old seam with `check`: capture's parent check is workspace-wide, but `src/check.rs` builds its `present` list per doc from `doc.all()`, so a case had to be written into the *same file* as its parent or `hi check` would immediately report `orphan-case` on the line capture had just written (hi: CAPTURE-4.a). Reverting to a family-first lookup re-opens that bug whenever a family is declared in one file's frontmatter and used in another. `a_case_lands_in_the_file_holding_its_parent` is the regression test, and it is built exactly out of that two-file shape.
- **The parent lookup spans retired criteria, and so does `check`'s `present`.** So a case under a retired parent is accepted and is not an orphan. `Doc::insert`'s `insertion_point` only scans active criteria, so that case joins the end of the family's active block rather than sitting under the retired line, while `render_criterion` still indents it by its own depth. Reproduced against the release binary: with `SEND-1` and `SEND-2` active and `SEND-3` retired, `hi SEND-3.a "a case of the retired one"` exits 0, writes `  - **SEND-3.a**  a case of the retired one` directly beneath `- **SEND-2**  two.`, and `hi check` then reports the file clean. The file therefore renders `SEND-3.a` as a case of `SEND-2`, which it is not. That is a consequence, not a decision; if it ever needs changing, it is a `doc` change (teach `insertion_point` about `self.retired`) or a `capture` one (refuse the case outright), and it wants a criterion of its own either way.
- The next-free hint is built by hand as `Id { family, levels: vec![Level::Number(workspace.next_free(&id.family))] }`, which is always a top-level number, even when the rejected id was `SEND-2.a`. That is intentional: the person is being told where the family currently ends, not where to graft a case.
- **Retired ids count as taken.** `Workspace::find_id` iterates `Doc::all()`, which chains active and retired criteria, so capture cannot resurrect a retired number. `Workspace::next_free` likewise maxes over `all()`, so retiring `SEND-3` still leaves `SEND-4` as next (DECISIONS.md §8.3).
- **Placement is delegated.** Capture computes no line numbers. `Doc::insert` owns the "a case lands directly under its parent" behavior (hi: CAPTURE-4), opens a `## Criteria` section when the file has none (hi: CAPTURE-7), and adds the family to the file's frontmatter `families:` list if it was missing. If a placement bug shows up, it is a `doc` bug, not a capture bug. But `accepts_a_case_under_an_existing_parent` lives here and is the regression that catches it.
- **The write is atomic and must stay that way.** `Doc::save` goes through `doc::write_atomically`: sibling `.<name>.hi-tmp`, `write_all`, `flush`, `sync_all`, `fs::rename`, with the temp file removed on any failure (hi: FILE-8). The obvious "simplification" is `fs::write`, which truncates the target first. A write that dies partway then destroys criteria the person already had. Do not make that change. `create_file`'s scaffold is still a plain `fs::write` on purpose: the path has just been checked not to exist, so there is nothing to lose.
- **A fenced code block is invisible to capture's duplicate check.** `Doc::parse` treats ``` and `~~~` fences as opaque (hi: FILE-9), so ids shown inside an example in someone's `## Intent` are prose. They are in neither `criteria` nor `retired`, so `Workspace::find_id` will not find them and `Workspace::next_free` will not count them. That is deliberate (documenting the format in your own file must not reserve ids), but it means "this id is visibly in the file" and "capture thinks this id is taken" are not the same statement. The same is true of `Doc::stray`, the criterion-shaped lines outside every section, which `Doc::all()` does not chain; `check` reports those as `stray-criterion` (hi: CHECK-2.e).

## Files to Read First

- `src/capture.rs` is about 110 lines of logic plus the inline `#[cfg(test)]` module. The tests are the clearest statement of the contract; read them before changing a message string.
- `src/workspace.rs` holds `find_id`, `next_free`, `doc_for_family`, `rel`, and `find`/`holds_hi_files`. `doc_for_family` resolves by frontmatter declaration **first** and by actual use second, which is why a file can hold a family it never declared, and why capture resolves a case by its parent before asking it. `find` will not adopt a `hi/` directory that holds no file with `hi:` frontmatter, because `hi` is also the ISO code for Hindi (hi: CAPTURE-6); `holds_hi_files` strips a leading BOM before looking for that key, so a BOM'd file still counts as a workspace. `find` also **stops** at a `.git`, rather than treating it as a last-resort fallback and walking on: a repository nested inside another anchors to itself and captures into its own `hi/` (hi: CAPTURE-10). `rel` joins with `/` on every platform, because its output reaches exported JSON, issue bodies and markdown links (hi: FILE-12).
- `src/doc.rs` has `Doc::insert` (which now also opens a `## Criteria` section when there is none) and its private `insertion_point`, plus `new_file_text` (the scaffold for a new family file), `rewrite_families` (style-preserving), `to_text`, `save`, the public `write_atomically`, and `render_criterion`, which joins `text.split_whitespace()` with single spaces and returns exactly one line: `{indent}- **{id}**  {sentence}`, where the indent is two spaces per level below the first. There is no wrapping and no wrap width; DECISIONS.md §10.1 records that the first renderer wrapped and that wrapping was removed (hi: FILE-6), and §12 records why the surviving line became a markdown list item rather than a bare one (hi: FILE-1.b, FILE-1.c). The reading side is `strip_bullet`, `strip_emphasis` and `is_criterion_line`, which between them let a hand-written criterion arrive with or without a bullet and with or without the bold id (hi: FILE-14). That asymmetry is why a fixture seeded with `SEND-1  I hit enter.` parses fine even though capture would have written `- **SEND-1**  I hit enter.`; do not "fix" a fixture into the bullet form and assume nothing is being covered.
- Read `src/id.rs` for `Id::parse`, `Id::parent`, `IdError`'s `Display` (capture interpolates it verbatim into its error, including the newer `PaddedLevel` variant), and `looks_like_id`, whose family test is case-insensitive while `Id::parse`'s is not: that gap is deliberate, and it is what turns `send-2` into a reported error instead of silent prose (hi: CHECK-2.d).
- `src/main.rs` covers `peel_root`, the `args_os` collection, and `run_capture(root, raw_id, rest)`.
- `tests/cli.rs` is the integration layer that drives the real binary; the capture tests there are the only coverage of argv routing, `--root`, exit codes, and the stdout/stderr split.
- `hi/capture.md` is the human intent this module serves, CAPTURE-1 through CAPTURE-11.
- `DECISIONS.md` §6 "Capture" has the table of what each input shape does, and the worked console example the error messages match.

## Current Status

Fully implemented and covered by eight inline unit tests, all passing, plus the capture tests in `tests/cli.rs`, which drive the real binary. The integration layer is what covers the parts capture cannot see from inside: the id-shaped dispatch (including a wrongly cased id and an ordinary hyphenated word), `--root` peeling in both directions, a non-UTF-8 argument, exit code 1 on a refusal, stdout staying empty on a refusal, byte-for-byte comparison of the file before and after a refused run, the repository boundary that `Workspace::find` stops at, and what a captured file actually looks like once rendered (`a_hi_file_renders_as_a_list_not_a_wall_of_text`, which captures three criteria through the binary and asserts the exact list form, the nesting indent, and that the result parses back to the same three).

Two non-obvious behaviors a future agent should know about, both visible in `create_file`:

1. **An existing file is adopted, not overwritten.** If `hi/<stem>.md` already exists but does not declare or use the family, `create_file` loads it with `Doc::load` and pushes it onto `workspace.docs` rather than writing `new_file_text` over it. Nothing is destroyed. But `capture` still reports `created_file == true` for that path, because the flag is set from `doc_for_family` returning `None`, not from a file actually being written. The CLI therefore prints `hi/billing.md  created` for a file it merely adopted. This is cosmetic and untested; treat the flag as "the family needed a home" rather than "a file was created".
2. **The adopted file is pushed as a second copy.** `Workspace::load` has already loaded every `hi/*.md`, so adopting `hi/billing.md` leaves two `Doc` values for the same path in `workspace.docs`, and the stale one is the earlier entry. Harmless today because the process exits right after a single capture, and the fresh copy is the one that gets inserted into and saved. It becomes a real bug the moment anything captures twice against one `Workspace`, so any future batch-capture path must de-duplicate by path first.

There is also a narrow ordering wrinkle: `create_file` writes the scaffold file **before** `Doc::insert` runs. A failure inside `insert` or `save` (both are `Result`) would leave a criterion-less family file on disk. No known input reaches that state, and it is an I/O failure rather than a refusal, so hi: CAPTURE-5 is not violated by it; but a strict reading of "nothing is written" would want the scaffold buffered until the insert succeeds. Note this is the one write capture makes that is *not* atomic, and deliberately so: the path has just been checked not to exist, so `fs::write` has nothing to truncate. Every write to a file that already had content goes through `Doc::save` and `write_atomically`.

One more thing worth knowing about the adoption path: because `Doc::insert` now opens a `## Criteria` section when the file has none, an adopted `hi/<stem>.md` no longer has to look like a hi file at all. Any markdown with frontmatter will do. The frontmatter is still required, though: `rewrite_families` is the only thing that can refuse there, and it refuses a file with no `---` block.

## Notes

- Error strings are asserted on by tests and shown verbatim to the person. `refuses_an_id_that_already_exists` matches `already exists` and `next free is SEND-2`; `refuses_a_case_with_no_parent` matches `needs a parent SEND-4`; `tests/cli.rs` matches the same strings on stderr, plus `leading zero` for a padded id, `not valid UTF-8` for a bad argument, and `not a repository` when discovery finds nothing. The punctuation that joins `'{raw_id}' is not a valid id` to `{err}` and the double space in `hint:  next free is` are both deliberate and match the console transcript in DECISIONS.md §6. The empty-sentence refusal is one sentence, `a criterion needs a sentence. Say what you actually want`, with a capital S on the second half.
- Capture's error text for a bad id is `IdError`'s `Display` interpolated whole, so adding a variant to `IdError` changes capture's messages without touching this module. `PaddedLevel` arrived that way (hi: ID-1.c).
- `title_for` handles the empty-family case by falling through to the lowercased input, so it cannot panic. It is unreachable in practice because `Id::parse` rejects an empty family first.
- `title_for` uppercases only the first character: `TWO_FACTOR` becomes `Two factor`, not `Two Factor`.
- Underscore handling differs between the two derivations and that is intended. The file stem uses `-` (`hi/two-factor.md`) while the title uses a space (`Two factor`).
- **A missing trailing newline is not round-tripped.** `Doc::to_text` appends the detected line ending to any non-empty output (the guard is `if self.trailing_newline || !out.is_empty()`), so capturing into a file whose last line carried no newline adds one, and `Doc::trailing_newline` only ever suppresses the ending for a file with no lines at all. Everything else does come back byte for byte (hi: FILE-4.a). Reproduced against the built binary. If that final byte is meant to round-trip, the fix is in `doc`, not here.
- Capture never touches `INTENT.md`. Regenerating the feature index is `hi index` (`src/out.rs`), run separately.
- Adding a criterion is the only mutation. If a future verb needs to edit or retire one, it belongs in a new module. Capture's guarantee that it only ever appends is what makes it safe to run without thinking.
