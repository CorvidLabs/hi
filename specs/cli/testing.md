## Automated Testing

This module *is* the automated testing layer, so what follows is what runs, and what each area of
it asserts. Sixty-seven tests: sixty-two at the top level and five inside `#[cfg(unix)] mod nudge`.
Run them with `cargo test --test cli`, a single one with `cargo test --test cli <name>`, or the
whole gate with `fledge lanes run verify`. The suite finishes in under two seconds despite spawning
a process per assertion.

| Test File | Type | What It Covers |
|-----------|------|----------------|
| `tests/cli.rs` | Integration, spawns `CARGO_BIN_EXE_hi` | Everything only a process has: argv routing, exit codes, the stdout/stderr split, and the bytes on disk afterwards |
| `tests/cli.rs` (`Repo::new`) | Fixture helper | `<tmp>/hi-cli-<pid>-<name>/` with an empty `hi/`. Cannot exercise a first capture — `hi/` already exists |
| `tests/cli.rs` (`Repo::with_chat`) | Fixture helper | `Repo::new` plus `hi/chat.md`: `families: [SEND]`, an `## Intent`, and a **bare** `SEND-1  I hit enter and it shows up.` on line 10. Both the bare form (hi: FILE-14) and the line number (quoted by the duplicate-id message) are load-bearing |
| `tests/cli.rs` (`Repo::bare`) | Fixture helper | A `.git` and no `hi/`. The only state the bootstrap lock defect is reachable from (DECISIONS.md §33) |
| `tests/cli.rs` (`listing`) | Assertion helper | Every path under the root with its bytes, sorted. The strongest "wrote nothing" assertion in the repository |
| `tests/cli.rs` (`future_format`) | Fixture helper | A repository whose criteria file declares `hi: 2` (hi: FILE-25) |
| `tests/cli.rs` (`HAND_WRITTEN_INTENT`) | Fixture constant | Prose either side of a generated block whose count is already wrong, so a correction cannot be confused with the block never being touched |
| `tests/cli.rs` (`mod nudge`) | Integration, unix only, spawns `bin/fledge-hi-nudge` | The fledge lifecycle hook, driven as fledge drives it, from a working directory that is deliberately not the repository |

## Manual Testing

- [ ] Run `cargo test --test cli` twice at once in two terminals and confirm nothing flakes. Every fixture carries a pid except `outside_a_repository_it_says_so_rather_than_guessing`, which is the one that would collide.
- [ ] `cargo clean -p human-intent && cargo test --test cli` whenever a result here disagrees with what `./target/release/hi` does by hand. A stale binary has twice made a passing change look like a code bug.
- [ ] Rewrite `Repo::with_chat`'s seeded criterion into capture's own list form and confirm the suite still passes. It will, and it covers less. That is the weakening DECISIONS.md §26 is about, and nothing automated catches it.
- [ ] Seed `HAND_WRITTEN_INTENT` with the correct count and confirm `a_capture_refreshes_the_feature_list` still passes. It will, without the block ever being touched.
- [ ] Change one fixture in `an_id_is_never_handed_out_twice` to use `Repo::new` where it used `Repo::bare` and confirm the bootstrap coverage disappears silently.
- [ ] Run the suite on Windows and confirm the concurrency tests pass. The one refusal ever observed in `concurrent_captures_into_a_repository_with_no_hi_directory_all_land` was a lock handoff there.
- [ ] Run `sh scripts/view-behaves.sh` after changing anything the page does. `view_writes_a_self_contained_page` asserts on the HTML going in and two bugs shipped past exactly that kind of assertion.
- [ ] Break `bin/fledge-hi-nudge` deliberately (make it `exit 1`) and confirm `no_path_through_the_hook_can_abort_a_push` fails. It is the one test here protecting somebody else's command.

## Edge Cases & Boundary Conditions

| Scenario | Expected Behavior |
|----------|-------------------|
| Two `cargo test` runs at once | Safe everywhere except `outside_a_repository_it_says_so_rather_than_guessing`, whose `<tmp>/hi-cli-norepo` path carries no pid |
| `target/debug/hi` is stale | `CARGO_BIN_EXE_hi` makes cargo rebuild, so the suite is safe; a *manual* comparison against a stale binary is not |
| A fixture is written in capture's own list form | The test passes and covers less. Nothing automated notices |
| A generated count is seeded correctly | The refresh assertion passes without the block being touched. Nothing automated notices |
| A test about a first capture is built on `Repo::new` | Passes for the wrong reason; `hi/` exists, so `lock::acquire` never creates it |
| A line is added to `Repo::with_chat`'s fixture | The duplicate-id message quotes line 10; other assertions and `specs/capture/` both read that number |
| A criterion's *text* contains `src=` or `https://` | `view_writes_a_self_contained_page` would fail, because its assertions are substring tests over the whole page rather than over the markup |
| The `not lowercase` wording in `check` changes | `a_criterion_in_a_file_hi_skips_is_reported_rather_than_vanishing` fails. That string is `check`'s wording for `StrayPlace::UnreadFile` and is a contract in two places |
| `gh` is absent from the machine | Nothing fails. No test exercises `hi issue --create` |
| Running on Windows | Sixty-five of the sixty-seven run. `a_non_utf8_argument_is_reported_not_panicked` and `mod nudge` are `#[cfg(unix)]` |
| A concurrency test refuses one id and succeeds the rest | A failure, with every refusal's stderr in the message. An id nobody else asked for is free |
| The order in which two concurrent processes land | Unspecified and unasserted. Only the state afterwards is asserted |
| `hi check` exits 0 over a file that is actually broken | What several of these tests exist to catch; it is why they assert on `check` both before and after the operation |
